# Lib

## Cell-tile rendering and highlight-filter UI are shared between Rows/Show and the Cells map
Rows/Show.vue (one row's cell×flat grid) and Cells/Index.vue (the warehouse map: one flat's row×cell-number grid, with flat-tab navigation) both render individual cells via the shared CellSlot.vue component and share highlight-filter state/logic via CellHighlightFilters.vue + lib/cellHighlight.ts (matchesCellHighlight, emptyCellHighlightFilters). The date/state predicates themselves (isCellExpiringWithin, isCellExpired, isCellStale) live in lib/cellStatus.ts, whose only importer is cellHighlight.ts — the pages and components reach them exclusively through `matchesCellHighlight`, so add a new predicate there rather than importing cellStatus.ts directly into a component. The actual highlight matching (state/expired/expires-within-days/product/stale-after-days) is purely client-side — the whole page's cells are already loaded in one request — never wire matching itself into a router.get. Cells/Index.vue also uses `matchesCellHighlight` against a second, lighter prop — `cellHighlightSamples` (all flats, not just the one on screen) — to render a per-flat match-count badge on each flat tab and a warehouse-wide total; see controllers-admin.md for that prop and the `MatchableCell` structural type the matching functions accept to support it. Cells/Index.vue is the one exception that DOES touch router.get: its `highlightFilters` deep-link-seeds from the dashboard URL (`initialHighlight`/`CellHighlightSeed`), and `goToFlat`/`onSearchSubmit` re-serialize the current filters back into the query via a local `highlightQuery()` helper so switching flats or searching doesn't drop them from the URL — see components-js-lib.md. CellHighlightFilters.vue's model is a reactive() object mutated in place (v-model on nested fields, Object.assign in clear()); it never emits update:modelValue, so pass it with :model-value="..." not v-model, and the parent must own a reactive(), not a plain ref. There is no automatic/filterless expiry emphasis anywhere — CellSlot has no expiry border, badge, or colored expiration text of its own; the only emphasis a cell ever gets is the highlight ring (ring-blue-500) when it matches an *explicitly applied* highlight filter. `isCellExpiringWithin` excludes already-past-due pallets (today-through-N-days-out only); `isCellExpired` is the separate helper/filter for "already overdue" — see components-js-lib.md. This was a deliberate removal of a prior "expiring soon window" (ExpiringDaysInput/expiringDays/expiringSoonUntil) feature that duplicated the expires-within-days highlight filter and auto-emphasized expired/soon cells without the user choosing to; don't reintroduce a parallel expiry-window mechanism outside the highlight filters. CellSlot also has no staleness badge — a stale match is communicated only by the same highlight ring, not a separate icon, so a pallet that's both expiring and stale doesn't get overlapping badges. Cells/Index.vue's rotate buttons don't spin the grid via CSS — lib/mapViewport.ts's mapOrientation(rotationDegrees) drives an actual layout swap (bands stacked as rows vs. laid out as side-by-side columns, cell-number order within each band, and which edge the band label sits on) so cell text always stays upright; see mapOrientation's doc comment for the derivation. A band is always identified by its row letter and always rendered in `rows` order — rotation never reorders which row comes before which other, so the row headers stay beside each other in the same sequence regardless of rotation direction; only the band axis direction, item order, and label edge change. Whenever the band label sits at the far edge (bandLabelAtEnd) or bands run as columns (bandsAsColumns), shorter rows are padded out to `maxCellsCount` with cell-unavailable placeholders so every band's label lines up flush; otherwise (bands as rows with the label at the near edge, the 0deg case) rows are left ragged/unpadded, showing only their own cell count. The shared cell-number header row only renders when bands are NOT columns — there's no equivalent header for column layouts. useMapViewport()'s reset() only recenters pan and zoom — it deliberately leaves rotation untouched, since "reset view" shouldn't discard the user's chosen map orientation; rotateLeft()/rotateRight() recenter pan (reset panX/panY to 0) because a stale pan offset from the old orientation reads as wrong once the axes swap. The rotate/reset recenter (rotateLeftAndRecenter/rotateRightAndRecenter/resetViewAndRecenter in Index.vue) suppresses the pan CSS transition (suppressPanTransition) for the reset-then-measure-then-recenter sequence — centerFirstCellInViewport() reads live layout via getBoundingClientRect() right after the DOM patches, and measuring while the transition is still interpolating reads a moving target, drifting the pan further off-target with every rotation until the map ends up panned entirely outside the viewport; suppressing the transition makes the measurement exact, then it's restored so drag/zoom keep animating normally.
